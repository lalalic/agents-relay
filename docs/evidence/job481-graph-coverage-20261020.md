# Job 481 canonical Graph inventory and coverage gate

## Inventory decision

The repository has 17 Mermaid files: 16 executable Graph DSL files and the dashboard-only navigation `workflow/main.mmd`. All 16 executable files have production loading references; the navigation entry has dashboard usage. **No Graph was deleted**: there is no confirmed unused graph in this inventory, and deleting a live graph would remove policy.

The new `test/verification/graph-inventory.test.mjs` is wired into `npm run test:verification:l1`. It fails if an executable Graph is orphaned, silently removed, cannot parse, has invalid declaration binding, contains ambiguous decisions with production-consistent dependency facts, or has a declared edge not exercised by the L1 decision-path exploration.

The test enumerates every state input, all Boolean combinations of the guards reachable from that input (up to 16 guard identities per input), evaluates production GraphRuntime, verifies actions/target states, records traversed edges, and rejects uncovered declared edges. For `task-lifecycle.mmd`, one impossible input assignment is ruled out by the production `reconcileTaskDependencies` invariant: `dependenciesUnsatisfied=true` implies `runnable=false`. It does not skip an executable path.

## Scope and limitations

- **L1 Graph DSL decision-path coverage:** all 16 executable Graphs, every declared edge in these graphs, with synthetic guard facts. This is not proof that all concrete callers populate correct facts or that real system actions succeeded.
- **L3 production scenarios:** independent, isolated SQLite, event ingress, Reconciler, Graph-selected effects and recovery tests are executed separately. Do not interpret an L1 full edge count as an L3 full-path assertion.
- **L3 Job 481 acceptance gates:** all 11 named isolated Graph/Reconciler/SQLite recovery paths now have positive causal evidence, including terminal `planner.failed` → Plan-specific Troubleshooter → new Plan → Objective completion. This does not constitute exhaustive L3 path coverage or live provider/notification delivery.
- **Provider/notification/browser:** real negative L2 role tests, production user-visible human escalation notifier and full browser Dashboard E2E remain not verified.

CI gate: `npm run test:verification:l1` (including graph inventory), `npm run test:verification:l3`, and `npm run test:verification`. The existing 11-path acceptance report is regenerated by `npm run test:verification:matrix`.

Do not change the Graph/runtime authority to satisfy a test by asserting fabricated transitions. In particular, production facts must not be replaced by synthetic flags when certifying L3.
