# Dashboard and PWA

The framework-free `dashboard/` tree is the frontend authority. `rust/src/dashboard.rs` serves HTTP/static/PWA/SSE; `dashboard_api.rs`, `dashboard_actions.rs` and `dashboard_data.rs` translate API requests to canonical runtime facts/actions. The UI must not own independent lifecycle state. Keep live API filters, ordering before pagination, explicit accessible Refresh, client-side filtering between refreshes and newest-20 display limit.

Mobile: one Search/Status/Repository/Refresh row without Reset; borderless accessible header icons; durable status coloring; native selects and visible focus; no horizontal overflow at 320–430 CSS pixels. Keep visual layout and interaction consistent across desktop/mobile.

Serve the shell without stale runtime state. The service worker may cache allowlisted static resources, never navigation, live API, events or credentials. Version and refresh consult the live backend. Use an authenticated trusted HTTPS boundary for remote devices; do not expose local Relay API publicly.

The selected Job header shows a one-line ellipsized title, compact icon-only JEL, Report and Objective actions (in that order), with mobile Back preserved. The Job list retains Refresh; the selected Job header has no separate Refresh. The JEL icon opens the lifecycle chart directly; there is no JEL cell and the viewer has no report control. Task detail shows the selected task title with matching compact Report and Input icons on one non-wrapping row. The input dialog keeps the original task input and, when available, shows the durable task result as a separate Conclusion. Worker threads link to validated Codex thread IDs using each stored thread route. For Neo profile threads, the Dashboard makes a bounded read-only exact `codexThreadId` lookup in the local Models Gateway session directory and exposes only the matching validated ChatGPT URL; missing, malformed, duplicate or unreadable mappings remain unavailable. The default directory is `~/.local/share/neo/model-gateway/sessions/` under the daemon's `HOME`; `AGENTS_RELAY_NEO_MODEL_GATEWAY_SESSION_DIR` overrides it for isolated setups. Reports open the latest exact-scope saved report for a settled Job/Task if its original capture is less than seven days old and no older than the scope’s durable update. Otherwise they generate and display a new report. Running scopes always generate. Neo Eval remains the sole persistent report store; older historical artifacts are retained, and responses remain no-store. Execution reports use the normal authenticated Neo Dashboard Gateway POST route with its existing browser session and CSRF checks. Relay does not impose a report-specific hostname or proxy restriction; its existing listener boundary remains unchanged. The request-intent header prevents ordinary cross-site form submissions, and the Gateway synthesizes it on the local upstream request. No extra report credential is required. The report iframe remains sandboxed; fragment links scroll and expand targets within that frame without navigating the Dashboard.

Workflow inspection is a read-only presentation of canonical graphs and their registered symbols. `docs/workflow-symbol-index.md` is consumed by the Dashboard; keep its contract references valid. Do not make explanatory diagrams executable.

Run `scripts/test-dashboard-browser.sh` for UI, HTTP/SSE, runtime-status and publication changes before review/merge/release. Use isolated native fixtures and real Chrome, including desktop and mobile widths. Native tests include `native_dashboard_api`, `native_dashboard_pwa`, `native_dashboard_browser`, `native_dashboard_jel`. Real remote-device checks must be reported separately.

`runtimeStatus` is computed by the shared Rust runtime-status derivation. An active Job with no higher-precedence status and a latest `PLANNING` plan is shown as `PLANNING`; Dashboard list, detail and live snapshots consume that value without persisting a lifecycle transition.

Read-only Dashboard requests are bounded and transient failures retain the last verified Job/runtime view. Initial failures, missed events and SSE disconnects recover through authoritative inventory refresh, including periodic refresh while the stream is connected; an empty filtered result remains a valid empty result. Slow SSE clients cannot block the daemon or other subscribers.

Normal Job listing selects the newest 20 after applying the existing filters and ordering to compact SQLite metadata, then hydrates those IDs with joined PR facts and publication state in the same read transaction. The explicit full-inventory request retains its full snapshot contract. Status uses COUNT, runtime summary reads ACTIVE jobs, and SSE observes compact revision metadata and hydrates changed jobs only. Derived SQLite indexes support active and pending-delivery queries.

Neo Mobile uses authenticated owner-scoped `/api/mobile/jobs` capabilities `pausable`, `recoverable` (resume a durably paused Job), and `cancellable`. `POST /api/mobile/job-pause` and `/api/mobile/job-resume` take `{id, repository}`, recheck unique identity and lifecycle, invoke canonical `job.pause`/`job.resume` control, and return only the sanitized Job readback. PAUSED in the mobile projection reflects persisted pause metadata, not a new lifecycle state. No general control access is needed on mobile.

The authenticated Dashboard supports `#/jel/ENCODED_REPOSITORY%7CJOB_ID` for Mobile handoff. It loads the exact scoped completed Job regardless of active filters or pagination and opens the same canonical JEL viewer; mismatched or unavailable Jobs fail closed.

Neo Mobile opens completed Job JEL in-app using authenticated `GET /api/mobile/job-jel?id=ID&repo=REPO`. The response `relay.jel.v1` includes only the scoped lifecycle facts and the exact static canonical `jel-function.js` generator, not private execution data or credentials. Mobile executes it with its bundled Mermaid renderer inside a local, network-disabled WebView without native bridges or browser login.
