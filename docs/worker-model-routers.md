# Execution Router

All model-backed execution entry points (Planner, Implementation, Reviewer, standalone Outcome/Preflight Review and detached CLI) use the shared Router. Profile discovery supplies configured model routes; usage observations and hard constraints gate eligibility. Never manufacture a candidate or let an advisory preference override hard eligibility. One decision selects worker/provider/model/profile/reasoning. Use verified provider facts; do not silently omit required observations.

`[routing-instruction]` is opaque user guidance, not code. The current configured routes, rules, explicit constraints and Agent/Job preferences are inputs to the shared policy. Job preferences are advisory and apply to eligible unpinned normal work; independent Final Review does not inherit ordinary Job hints. Exact Task overrides remain constraints. The current decision engine is Jev; when a decision fails, deterministic eligible-route fallback applies, never a second model decision. No eligible route is an error. Confirmed runtime failure can exclude that route and retry safely through the existing Task Graph.

The detached `agents-relay route --input-file request.json` calls the same routing implementation and obtains daemon-owned provider observations unless explicit isolated facts are provided. It selects a route, not an execution, and creates no Job. `agents-relay infer --help` exposes synchronous text/image inference using that same ingress and shared Codex route encoder. It creates no Job or Task; callers must supply a verified vision profile allowlist and authorize external transfer. Consult `agents-relay route --help` and the [Agent Definition Contract](../skills/agents-relay/contracts/agent-contract.md) for input fields.
