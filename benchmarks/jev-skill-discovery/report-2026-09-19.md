# Jev skill-discovery benchmark report — 2026-09-19

## Outcome

The frozen benchmark contains 26 historical/synthetic tasks × 4 controlled candidate-set sizes (4/8/16/24 choices). Jev was repeated three times for 312 decisions; GPT-5.6 Sol high reasoning was run once on the same 104 case/size combinations.

Cloudflare Workers AI transport is currently blocked by the account's HTTP 402 / code 2021 insufficient-balance response already validated in this PR. No billing changes were made. Behavioral quality was therefore measured with the same `typesafe/jev-1.13` release via OpenRouter and must not be treated as Cloudflare latency/cost data.

## Measured results

Jev behavioral proxy:
- 312/312 successful decisions.
- 98.72% exact match.
- 0 false-positive skill loads on expected `none`.
- 4 missed required-skill decisions.
- 10-bin ECE 0.0302.
- 5.77% fallback at confidence < 0.70.
- p50 370.8 ms; p95 934.6 ms.
- 402,894 input tokens; 43,945 output tokens.
- reported cost $0.01692.

Strong GPT-5.6 Sol high-reasoning baseline:
- 104/104 successful decisions.
- 97.12% exact match.
- 0 false-positive skill loads.
- 3 missed required-skill decisions.
- p50 1586.7 ms; p95 3038.8 ms.
- 61,374 total tokens.
- reported cost $0.16848.

All four Jev mistakes were low-confidence and would have fallen back under the 0.70 threshold. There were no observed high-confidence Jev mistakes in this replay.

## Candidate-set sensitivity

Jev exact match by total choices: 4 → 96.15%, 8 → 100%, 16 → 100%, 24 → 98.72%. Mean confidence fell from 0.968 at 4 choices to 0.944 at 24 choices. The pattern is not monotonic enough to infer a general scaling law from 26 fixtures.

## Failure modes

The clearest ambiguity is boundary overlap between orchestrator and runtime skills. For the managed-PR fixture, Jev repeatedly selected `agents-relay` rather than `xchat-orchestrator` when only four choices were present, but confidence stayed at 0.54–0.56. One 24-choice repetition selected `none` instead of `ponytail` at 0.47 confidence.

The strong judge also disagreed on overlapping skill responsibilities in some candidate sets, which reinforces that fixture labels and skill descriptions need independent review before treating aggregate accuracy as a production-quality estimate.

## Integration recommendation

Keep production skill loading unchanged. Continue Jev only as an optional typed semantic recommendation after deterministic rules, with:
1. explicit/mandatory skill rules first;
2. deterministic candidate filtering and project-local precedence;
3. Jev Choice over the remaining controlled candidates;
4. conservative confidence/policy gate;
5. existing reasoning discovery on low confidence, malformed output, or provider failure.

The current 0.70 threshold is descriptive, not a production setting. It was observed on this same fixture set and therefore needs held-out calibration.

## Next evidence required

- Funded/approved Cloudflare Workers AI replay using the identical frozen fixtures.
- At least 200 independently labeled historical XChat/Agents Relay tasks.
- Held-out threshold calibration.
- More overlapping-skill cases (especially orchestrator vs agents-relay, browser vs app-specific skill, generic coding vs ponytail).
- Explicit-trigger fixtures proving Jev can never override `#skill-name` or mandatory bootstrap rules.
