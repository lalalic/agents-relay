# Execution Checkpoint Fallback Contract

- Applies to managed Model executions with an existing Execution ID. Isolated evaluations and unbound executions do not use this fallback.
- Use the model runtime's normal checkpoint mechanism. Do not create periodic checkpoints or add normal-path tool calls.
- Only if the built-in checkpoint save fails or is unavailable before an explicit context reset/compaction, use the local Shell (not the failing context-file tools) to save a concise checkpoint at `/tmp/relay-checkpoint-<executionId>.md`, replacing `<executionId>` with the exact existing Execution ID. No additional binding or discovery is needed. Validate that the ID contains only ASCII letters, digits, hyphens or underscores; otherwise stop and report the unsafe identity. Include execution identity, completed work, actual validation evidence, unresolved issues, pending actions and the exact next step, especially completion submission. Never record secrets or fabricate evidence.
- Use owner-only permissions (`umask 077`, file mode 0600), reject symlinks and foreign-owned or unsafe existing files, and atomically replace the checkpoint using a securely created temporary file in the same directory. Read it back and verify identity and content. Do not voluntarily reset context if both checkpoint methods failed.
- After context loss, if normal checkpoint/history recovery is unavailable or incomplete, derive the same path from the existing Execution ID and read the local checkpoint before repeating work; verify its identity, ownership, permissions, existing artifacts, state and receipts. Continue only unfinished steps. If neither checkpoint is available, recover from actual durable Task/Plan evidence rather than assume prior work was completed.
- The checkpoint is a temporary recovery aid outside the Git checkout, not Task/Plan state, validation, approval or a completion receipt. Remove only this execution's verified fallback file after confirmed terminal acceptance when possible; leave failed or interrupted execution evidence for diagnosis. Never reuse another execution's checkpoint.
